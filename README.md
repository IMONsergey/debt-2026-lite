# DEBT TECH 2026

React + Vite, обычный CSS. Глобальная чистка: `codex/global-layout-cleanup`, созданная от `codex/new-sections-experiment`.

```sh
npm ci
npm run dev
```

Перед публикацией:

```sh
npm run check
```

Содержимое страницы: `src/data/content.js`. Секции: `src/components`. Порядок стилей: `src/styles/index.css`. Кнопки: `src/styles/ui.css`.

[Аудит и ограничения проверки](docs/global-layout-audit.md) · [Интеграция форм](docs/forms-integration.md).

## GitHub Pages

Workflow `pages.yml` этой ветки собирает проверенную версию в `/debt-2026-lite/cleanup/`. В том же артефакте сохраняются сайт из `main` в корне и `site-sandbox` в `/sandbox/`. Отправка коммита в `codex/global-layout-cleanup` запускает проверку, сборку и публикацию; другие ветки не изменяются.

Однократная настройка владельцем репозитория: **Settings → Environments → github-pages → Deployment branches and tags** — добавить точное имя ветки `codex/global-layout-cleanup`, сохранив разрешение для `main`. Пока разрешена только `main`, GitHub блокирует этап публикации. После добавления ветки повторно запустите неуспешный этап в Actions.

GitHub Pages не исполняет `/api/lead`. Только в Pages-артефакте адрес форм заменяется на существующий `https://debt-2026-lite.176.98.177.253.sslip.io/api/lead`. На сервере заявок необходимо добавить `https://imonsergey.github.io` к текущему списку `ALLOWED_ORIGINS` (или `ALLOWED_ORIGIN`, если используется он), сохранив остальные домены. Проверка `OPTIONS` 16 сентября 2026 года вернула 204 без разрешающих CORS-заголовков: до настройки отправка с Pages будет заблокирована браузером. Реальные заявки при проверке не отправляются.

У репозитория один Pages-артефакт. Старый workflow в `main` содержит только корень и `/sandbox/`: его повторный запуск удалит `/cleanup/` из публикации. В таком случае повторите запуск `pages.yml` из `codex/global-layout-cleanup`. Для постоянного сохранения всех трёх версий при публикации из `main` понадобится отдельно согласованное обновление его workflow.

`/api/lead` в Vercel перенаправляется в существующий сервис заявок. Для локального интерфейса backend не требуется; не отправляйте пробные заявки в рабочий сервис. Тесты отправки используют подставные ответы.

`npm run check` включает ESLint, тесты скидок и отправки, проверку ассетов и их бюджета, production build и статические проверки адаптивного CSS. Workflow `check.yml` выполняет их для этой ветки и pull request, затем проверяет сборку с префиксом GitHub Pages.

Изображения используют `ResponsiveImage` и `src/data/images.json`: полная версия + варианты 640/960 px, когда исходник больше. Все файлы готовы к публикации; Python в production не требуется. Для повторной генерации из исходников в истории Git: `python scripts/optimize-images.py` (Pillow с поддержкой WebP; нужен указанный в скрипте коммит). Бюджет папки `public/assets` — 14 МБ.

Заставка имеет отдельный `public/preloader.js`, чтобы показать ошибку даже при сбое загрузки приложения. Готовность первого экрана определяет `src/lib/page-ready.js`; картинки нижних секций не задерживают открытие страницы. Код диалогов загружается отдельно при открытии.

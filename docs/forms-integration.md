# Подключение форм DEBT TECH 2026

На сайте используются две формы:

- `early-registration-form` — ранняя регистрация;
- `stand-booking-form` — бронирование стенда.

Адрес обработчика задаётся в `index.html`:

```html
<meta name="debt-tech-forms-endpoint" content="https://example.ru/local/ajax/debt-tech-form.php" />
```

Фронтенд отправляет на этот адрес `POST` с заголовком `Content-Type: application/json`. Обработчик должен возвращать JSON:

```json
{
  "success": true,
  "lead_id": "12345"
}
```

При ошибке нужно вернуть HTTP-статус 4xx/5xx или ответ:

```json
{
  "success": false,
  "message": "Текст ошибки"
}
```

## Общие поля

| Поле | Назначение |
| --- | --- |
| `form_id` | Идентификатор формы |
| `event_id` | Всегда `debt-tech-2026` |
| `full_name` | ФИО |
| `company` | Компания |
| `phone` | Телефон |
| `email` | E-mail |
| `consent` | Согласие на обработку данных, `true` |
| `source_page` | Адрес страницы, с которой отправлена заявка |
| `submitted_at` | Дата и время в ISO 8601 |
| `tariff_id` | Идентификатор выбранного тарифа, если форма открыта из блока тарифов |
| `tariff_name` | Название выбранного тарифа |
| `tariff_price` | Стоимость выбранного тарифа |
| `website` | Скрытое антиспам-поле. Заявку с заполненным полем нужно отклонить |

Если в адресе страницы есть UTM-метки, дополнительно передаются `utm_source`, `utm_medium`, `utm_campaign`, `utm_content` и `utm_term`.

## Ранняя регистрация

`form_id`: `early-registration-form`

Дополнительные поля:

| Поле | Назначение |
| --- | --- |
| `participants_count` | Количество участников |
| `promo_code` | Промокод, необязательное поле |

## Бронирование стенда

`form_id`: `stand-booking-form`

Дополнительные поля:

| Поле | Назначение |
| --- | --- |
| `job_title` | Должность контактного лица, необязательное поле |
| `comment` | Комментарий и желаемый формат стенда, необязательное поле |

## Рекомендуемое сопоставление с Bitrix24

Обработчик на сервере создаёт лид или сделку через REST API Bitrix24. Базовые поля можно сопоставить так:

| Поле сайта | Поле Bitrix24 |
| --- | --- |
| `full_name` | `TITLE` и `NAME` |
| `company` | `COMPANY_TITLE` |
| `phone` | `PHONE` (`VALUE_TYPE: WORK`) |
| `email` | `EMAIL` (`VALUE_TYPE: WORK`) |
| `comment` | `COMMENTS` |
| `form_id` | отдельное пользовательское поле или источник заявки |
| `participants_count` | пользовательское поле лида/сделки |
| `promo_code` | пользовательское поле лида/сделки |
| `job_title` | `POST` |

Коды пользовательских полей вида `UF_CRM_...` зависят от конкретного портала Bitrix24. Их нужно создать в CRM и подставить в серверный обработчик.

Если заявки также нужно отправлять в Telegram, это лучше делать из того же серверного обработчика после успешного создания лида. Токен бота и вебхук Bitrix24 нельзя размещать в `index.html` или другом клиентском файле.

Для обработчика на другом домене необходимо разрешить CORS для домена сайта и методы `POST, OPTIONS`. При размещении обработчика на том же домене дополнительная настройка CORS не нужна.
